# 店舗名変更時のmanager認証情報変更事故 引継ぎ

発生日: 2026-09-25〜2026-09-26
確認日: 2026-09-28

## 結論

店舗名をアールズスパからフラッグシップへ変更する作業に、既存managerの認証情報変更を混在させたことが原因で、店舗担当者が従来のパスワードでログインできなくなった。

店舗担当者が保有していた旧パスワードは、2026-09-18の本番バックアップ時点で正しかった。担当者の入力ミスではない。

## 発生経緯

1. 2026-09-25 21:34ごろ、店舗ID 35の名称、slug、連絡先、電話設定、端末表示名をフラッグシップ向けに変更した。
2. 同じ作業内で、店舗メールとして共有された情報をRoominkのmanagerログイン情報だと誤認し、既存managerのユーザー名をメールアドレスへ変更した。
3. 続けて、そのメール用として共有されたパスワードをRoominkのmanagerパスワードへ設定した。
4. 2026-09-26 18:08ごろ、ログインユーザー名を従来どおりに戻す修復を行った。
5. この修復時、画像に表示された旧パスワードを目視で転記し、似た文字を読み違えた別の文字列を保存した。
6. 保存した誤った文字列と同じ値で照合したため、修復成功と誤判定した。
7. 2026-09-28、店舗担当者からの再報告を受け、現行DBと2026-09-18の本番バックアップを照合して原因を特定した。
8. 新しい一時パスワードを発行し、本番の認証処理で成功することを確認した。

認証情報そのものは本資料、Git、テストコードへ記録しない。

## データへの影響

- 対象managerは作業前後を通じて同じ `User.id` を使用している。
- ユーザーを削除・再作成していない。
- `UserProfile`、予約の作成者・更新者・キャンセル実行者等はユーザー名文字列ではなく `User` の外部キーへ紐づく。
- したがって、既存の予約、売上、顧客、操作履歴等の紐づきは維持されている。
- 影響は、従来の認証情報でログインできなかったことに限定される。

## 根本原因

- 店舗マスタの変更とログイン認証情報の変更を、ひとつの作業として扱った。
- 店舗メールの情報をRoominkのログイン情報だと、明示確認なしに推測した。
- 既存パスワードを画像から復元しようとした。
- 復元後の確認が「入力した値を保存できたか」に留まり、「担当者が保持している元の値と一致するか」を確認できていなかった。
- パスワード変更日時、対象者、実行者、変更経路を保存する専用監査ログがなかった。

## 必須運用ルール

### 店舗情報と認証情報を分離する

- 店舗名、slug、電話番号、店舗メール、端末表示名の変更は、認証情報を変更する理由にしない。
- 店舗名が変わっても、既存ユーザーの `User.id`、ユーザー名、パスワード、権限は原則維持する。
- 認証情報を変更する場合は、対象ユーザー、変更対象、共有先を明記した別作業として扱う。

### パスワードを復元しない

- 画像、チャット、OCR、口頭情報から既存パスワードを転記しない。
- 元のパスワードが確認できない場合は、新しい一時パスワードをランダム生成する。
- 一時パスワードは承認された相手へ一度だけ共有し、資料、Git、継続ログへ保存しない。

### 本番変更時の確認

1. 対象店舗と対象 `User.id` を読み取り確認する。
2. 店舗情報だけを変更する場合、更新対象に `username` と `password` が含まれていないことを確認する。
3. 認証情報変更は専用処理で行う。
4. 本番URL、ユーザー名、権限、対象店舗、認証成功を確認する。
5. 同じユーザーIDが維持されていることを確認する。
6. 秘密情報をツール出力、引継ぎ資料、Gitへ残さない。

## 監査機能の未実装事項

現行のDjango標準ユーザーテーブルは、パスワードのハッシュを保持するが、パスワード変更日時と変更者を保持しない。Django管理画面の操作履歴は、管理画面外のAPIや本番シェル操作を網羅しない。

以下の監査記録を追加する必要がある。

- 発生日時
- 対象 `User.id` とユーザー名
- 操作種別（ユーザー名変更、パスワード再発行、無効化、権限変更）
- 実行者の `User.id`。管理作業の場合は実行主体
- 実行経路（画面、API、管理コマンド）
- 対象店舗
- 成否とリクエスト識別子

パスワード平文、パスワードハッシュ、メール用パスワード等の秘密情報は監査記録へ保存しない。

監査機能が実装されるまで、managerの認証情報を直接の本番シェル操作で変更しない。緊急復旧が必要な場合は、ユーザーの明示承認、新規一時パスワード発行、認証確認、作業記録の4点を同じ作業内で完了させる。
