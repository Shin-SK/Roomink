# キャスト予定画面のUI改善・本番反映 引き継ぎ

## 対象

- キャストの出勤・予約予定を日付カードと選択日のタイムラインで表示。
- ホームは予約時間を優先して表示し、出勤確認後は確認欄を縮小。
- ホーム、予約、出勤予定、シフト申請のナビゲーション順に変更。
- 出勤予定の初回表示とルーム使用状況の「読み込み中...」を回転ローダーへ変更。スクリーンリーダー向けの読み込み状態名を付与。
- ログインパスワードの表示切替とルームの住所・地図リンクを追加。

## 変更範囲と注意

- `frontend/src/pages/cast/`、`frontend/src/components/LayoutCast.vue`、`frontend/src/pages/op/Login.vue`、`frontend/src/roomMap.js`、`core/views.py`、関連テスト。
- DBマイグレーション、決済、SMS送信、実顧客データの変更はない。
- 出勤予定APIは自分の店舗と自分の予約のみを返す設計を維持する。別店舗・他キャストの情報が混ざらないか本番確認時も注意する。
- 予約専用画面は従来の縦長レイアウトのまま。ホームと統一するUI改善は別作業。

## 検証

- `npm --prefix frontend run build`: 合格。
- `.venv/bin/python3 manage.py test core.test_cast_schedule core.test_cast_today_business_datetime --noinput`: 7件合格。
- ローカルのサンプルキャストで、出勤確認前後・予約表示・日付切替の画面を確認済み。確認済み状態の検証用データは元に戻した。
- ローダーの追加は既存のBootstrapスピナーを利用。実際の低速回線での見え方は本番公開後の確認項目。

## 本番反映後の確認

1. 本番の出勤予定画面の配信と初回ロード、週移動、日付切替、ルーム使用状況を確認。
2. キャストホームで予約時刻・出勤確認欄・ナビの表示を確認。
3. キャスト以外の権限でキャストAPIを利用できないことを確認。
4. Heroku APIの正常応答、Netlify配信、ブラウザのコンソールエラーを確認。
