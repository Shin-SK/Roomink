# 同名キャスト許容・スタッフ任意メール修正 引き継ぎ報告

## 概要

本番フルチェックで確認された以下2点を修正した。

1. 同一店舗で同名キャストを登録するとDB制約違反になり、APIが500を返す
2. スタッフ登録画面ではメールアドレスが任意表示だが、空文字をAPIへ送ると400になる

## 設計判断

- キャストの表示名は同一店舗内でも重複を許可する
- キャスト本人の識別には表示名やログインユーザー名ではなく、既存の `Cast.id` を使用する
- ログインユーザー名はキャストにログインアカウントが連携されている場合だけ存在するため、キャスト本体の一意キーにはしない
- CSV取込はこれまで表示名を更新キーにしていたため、同名キャストが2人以上いる場合は誤更新せず、個別編集を促す400応答で停止する
- 退店者の非表示・在籍状態管理は今回の不具合修正には含めない

## 変更ファイル

- `core/models.py`
  - `Cast` の `(store, name)` 一意制約を削除
- `core/migrations/0058_alter_cast_unique_together.py`
  - 上記DB制約を削除するmigration
- `core/serializers.py`
  - スタッフ作成・更新のメールアドレスで空文字を許可
- `core/services/cast_user.py`
  - CSV取込時、同名1件なら更新、0件なら作成、複数件なら安全に停止
- `core/views.py`
  - CSVの同名曖昧エラーを内容付き400として返却
- `core/test_cast_create_with_expense_templates.py`
  - 同名キャスト2件の登録成功と、CSV誤更新防止の回帰テストを追加
- `core/test_staff_optional_email.py`
  - 空メールでのスタッフ新規登録と、既存メールの空欄化テストを追加

## デプロイ時の注意

- release phaseでmigration `0058`を適用する
- migrationは一意制約を削除するだけで、既存キャスト・予約・ログインアカウントを更新しない
- rollbackで一意制約を戻す場合、デプロイ後に同名データが作られていると制約を再作成できないため、先に同名データの整理が必要

## デプロイ後の手動確認

1. 同じ店舗で同じ表示名のキャストを2人登録できる
2. 2人が異なるキャストIDとして一覧・APIに残る
3. 同名2人がいる状態のキャストCSV取込が、誤更新せず説明付きで停止する
4. メールアドレス空欄でスタッフを新規登録できる
5. 登録済みスタッフのメールアドレスを空欄へ戻せる

## 残課題

- 退店済みキャストを履歴には残しつつ、通常の予約・シフト候補から隠す「在籍／無効化」機能は別途検討が必要
- 同名キャストを運営画面で見分けやすくする管理ID・ユーザー名等の補助表示は、実運用で必要性を確認して追加する
