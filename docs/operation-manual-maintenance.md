# Roomink 操作マニュアルの更新ルール

## 正本

利用者向けの操作マニュアル本文は、`frontend/src/pages/op/manualData.js` を正本とする。
アプリ内の「設定 → 操作マニュアル」、キャスト向けマニュアル、お客様向けヘルプは、このデータを役割ごとに表示する。

Notionは本文の複製先にしない。更新の依頼、確認状況、担当、公開判断を管理し、この正本と該当する記事へリンクする。

## 機能変更時の確認

利用者が見る画面、操作、権限、表示条件、通知、計算結果が変わる変更では、実装と同じ変更単位で次のいずれかを記録する。

1. 既存記事を更新する。
2. 新しい記事を追加する。
3. 操作マニュアルへの影響はない。理由を変更記録に残す。

内部実装だけの変更、開発・ステージングの手順、未公開機能は、利用者向け操作マニュアルへ追加しない。

## 記事に含める内容

各記事は、対象者、入口となる画面、手順、完了を判断する表示、注意事項を持つ。
権限が異なる場合は、記事を分けるか、対象者ごとに手順を分ける。表示されない画面や利用できない権限を前提に書かない。

## 確認の順序

1. 実装された画面とAPIの権限を確認する。
2. マネージャー、スタッフ、キャスト、お客様のうち影響する役割を特定する。
3. マニュアルの新規・更新・不要を決める。
4. ローカルで該当記事、一覧表示、リンク先、役割ごとの表示制御を確認する。
5. UI変更を含む公開時は、通常のステージング確認と画面レビューにマニュアル表示も含める。

## Notionで管理する項目

- 機能または変更名
- マニュアル対応状況（不要 / 下書き / レビュー中 / 完了）
- 対象記事へのリンク
- 確認担当
- 根拠となる実装または確認結果

Notion上の説明文とアプリ内本文を並行して更新しない。本文の修正はこのリポジトリの正本で行い、Notionには更新結果を記録する。
